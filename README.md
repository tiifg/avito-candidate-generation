# avito-candidate-generation

## Подход

Решение - гибридный retrieval-пайплайн:

1. Текстовый поиск через TF-IDF (униграммы(1) + биграммы(2)) по объединенному тексту объявления (заголовок + описание + параметры + категория).
2. Бусты по категории и локации на основе маппингов, построенных из train.parquet.
3. Бусты за популярность объявления в train, рейтинг и число отзывов.
4. Fallback на популярность и рейтинг, если текстовых совпадений нет.

Итог - top-50 объявлений по скору для каждого запроса.

## Данные и признаки

Использованы все три файла: train.parquet, benchmark_queries.parquet, benchmark_items.parquet.

Из запроса:
- search_query - основной сигнал, повторяется трижды для веса.
- search_infm_params_text - фильтры, добавляют контекст.
- search_category - для буста по категории.
- search_location_id - для буста по локации.

Из объявления:
- item_title_raw - повторяется дважды, самый информативный текст.
- item_description_raw - добавляет контекст.
- item_infm_params_text - вид услуги, тип услуги.
- item_category_id, item_microcat_id -- для добавления как токенов cat_/mic_ в текст.
- item_location_id, item_rating, item_rating_reviews_count - для бустов.

Из train.parquet:
- item_id — для расчета популярности.
- пары (search_category, item_category_id) - для маппинга категорий.
- пары (search_location_id, item_location_id) - для маппинга локаций.

## Модели и алгоритмы

- TfidfVectorizer (scikit-learn): analyzer="word", ngram_range=(1,2), min_df=1, max_features=500_000, sublinear_tf=True, token_pattern=r"(?u)\b\w+\b".
- Косинусная близость через матричное умножение нормализованных TF-IDF-векторов.
- Эвристические бусты:
  - +0.30 * max_s за совпадение категории (через cat_map из train);
  - +0.20 * max_s за совпадение локации (через loc_map из train);
  - +0.05 * log1p (популярность в train);
  - +0.01 * рейтинг;
  - +0.005 * log1p (число отзывов).
- Батчинг по 100 запросов для экономии памяти.

## Проверка качества

Локальная валидация: train.parquet разбит на train_part (80%)
и valid_part (20%) по query_id, чтобы не было утечки.
Пайплайн обучался на train_part, метрика считалась на valid_part.

Recall@50 на валидации: 0.XX (baseline без бустов: 0.YY).

Формат answer.csv проверен скриптом check_answer.py:
- число строк = число запросов бенчмарка;
- query_id уникальны;
- не больше 50 item_id в строке;
- нет повторов внутри строки;
- все item_id есть в benchmark_items.parquet.

## Найденные ошибки и решения

1. **Потеря ведущих нулей в ID.** При чтении parquet pandas иногда
   парсит ID как число. Решение: astype(str) сразу после загрузки.

2. **MemoryError при расчёте скоров для всех запросов сразу.**
   Матрица 2452 × 189212 примерно 3.7 ГБ. Решение: батчинг по 100 запросов.

3. **Нулевые скоры для запросов без общих токенов с корпусом.**
   argsort нулевого массива дает произвольный порядок.
   Решение: fallback на популярность и рейтинг при max_s <= 0.

4. **Дублирование веса полей.** Если заголовок и описание содержат
   одни и те же слова, TF-IDF суммирует их вклад. Решение: повтор
   заголовка дважды для явного приоритета.

5. **NaN в рейтинге и числе отзывов.** Арифметика с NaN дает NaN.
   Решение: fillna(0) при подготовке массивов.

## Воспроизводимость

1. Установить зависимости: pip install -r requirements.txt
2. Положить train.parquet, benchmark_queries.parquet,
   benchmark_items.parquet в корень репозитория.
3. Запустить: python solution.py

Версии библиотек зафиксированы в requirements.txt.
Random seed не используется - решение детерминированное.
